## Affected Commands and Consumers

- source-generation batch: classifier → planner → generator → validator ordering
- Seoul official batch: one source classification reused by generation attempts
- preview generation: v2 artifacts and stage names
- audit bridge: classifier/generator/validator receipts and hashes
- holdout evaluation: v2 model identity and result fields

## Key Interactions to Verify

- classifier output is locked before deterministic planning
- generator response contains only `GeneratedDocumentIR`
- blind validator receives no source, target, route, rationale, or classifier evidence
- validation mismatch creates typed repair codes and reruns only generation/validation
- stage artifacts resume from the last valid checkpoint
- each prompt/model/policy change invalidates only its stage and downstream stages
- all v1 artifacts are retained but rejected for v2 resume
- no P1/P2 or `run_two_pass` API/export/report field remains

## Edge Cases

- invalid or missing source evidence
- `other` document form without and with `other_document_form`
- incompatible subject role or target subclause
- classifier and generator model equal; validator model equal to either
- empty or invalid generated IR
- invalid validator evidence
- every comparison mismatch independently and in combination
- retry limit reached, hard-case review, and excluded-after-retry
- interrupted run after each of classified/planned/generated/validated
- v1 contract or prompt/model hash mismatch

## Critical Paths

1. Compatible source succeeds through all stages.
2. Incompatible source is rejected before generator invocation.
3. Generator failure preserves classification and plan.
4. Validator failure preserves all upstream artifacts and resumes at validation.
5. Semantic mismatch produces repair codes and reuses classifier/plan.
6. Audit and report consumers read the final v2 artifact lineage.

## Accepted Untested Quality Risk

No live model is called, so prompt-following quality is not established. No grounded
source-to-generated comparison is implemented, so an original value copied into the
generated document can pass the blind validator.
