## Affected Pages/Routes

- `scripts/generate_from_source.py` — 원본문서 manifest를 받아 Pass 1 생성, Pass 2 독립 채점, 실행 저널 및 audit 산출물을 만드는 새 CLI.
- `scripts/audit_cs_generation.py` — 기존 generation audit 결과가 새 bridge 적용 뒤에도 변하지 않는지 회귀 확인.
- Opt-in live eval command — EC2의 민감 원문 manifest를 사용해 26개 source type, 24개 법적 subclause, C/S/O 및 counterfactual 생성을 검증.
- Opt-in PRISM classification eval command — 생성 없이 held-out 원문 C/S 약 166건 + O 100건을 생성 모델과 채점 모델이 각각 분류해 실제 라벨 정확도를 비교한다(약 532회 호출).

## Key Interactions to Verify

- 85페이지 이하 문서는 전체 입력을 사용하고 86페이지 이상 문서는 relevance 선별을 사용한다.
- Pass 1이 원본문서 분류와 route/target 선택을 한 번의 LLM 호출로 완료한다.
- `fully_synthetic`이면 P1 임시 IR을 폐기하고, 원문 없는 민감 5~8호 adapter가
  기존 생성기를 호출한 뒤 canonical block IR로 변환한다.
- Pass 2는 Pass 1의 답·이유·span을 받지 않고 생성된 IR만 독립 재분류한다.
- 생성 모델과 채점 모델 ID가 같으면 LLM 호출 전에 실패한다.
- 분류용 held-out manifest는 prompt 예시와 56-case live eval에서 제외되고, 고정 seed와 manifest hash로 재현된다.
- C/S 원본문서는 원래 조항을 사용하고 O 원본문서는 명시적인 counterfactual target을 사용한다.
- 행정상태 target은 P1이 변경하지 못하며, 상태명 메타데이터가 아니라
  상태별 필수 표현을 포함한 자연스러운 paragraph 문장으로 생성한다.
- 조항 없는 행정상태 단독 문서는 법적 O/null/null과 행정상태 finding을
  P2가 각각 반환하고, 계산된 최종 분류만 S가 된다.
- 법적 조항과 행정상태가 함께 있는 문서는 두 축을 모두 보존하고 각각 비교한다.
- source label과 target label이 별도 artifact와 최종 manifest에서 뒤바뀌지 않는다.
- 민감 5~8호 16개 subclause가 시나리오·template target·content point에 빠짐없이
  연결되고, 8호 `cornering`이 부동산 투기 시나리오로 대체되지 않는다.
- `fully_synthetic` 실패 결과에도 P1이 원문을 보고 만든 임시 IR이 남지 않는다.
- 불일치 행과 잘못된 evidence span 행이 review sample에 반드시 포함된다.
- Pass 2 또는 audit 실패 후 재개할 때 이미 성공한 LLM 단계를 다시 호출하지 않는다.
- prompt bundle, model 또는 source hash가 바뀌면 필요한 단계부터 정확히 무효화한다.
- 기존 audit fixture의 coverage, duplicate, format 및 run-status 결과가 변하지 않는다.

## Edge Cases

- 0, 1, 85, 86, 723페이지 문서.
- 근거가 첫 페이지, 중간 페이지, 마지막 페이지에 있는 문서.
- relevance 모델이 빈 결과, 중복 block, 존재하지 않는 page/block 또는 context 초과 결과를 반환.
- LLM 거부, 빈 응답, JSON 파싱 실패, Pydantic 검증 실패 및 SDK 최종 오류.
- source type `other`, 조항 없음(O), 허용되지 않은 subclause 및 조건부 필드 불일치.
- 생성 IR의 빈 block 목록, 빈 본문, 잘못된 표 행 길이 및 중복 block ID.
- Pass 2의 완전 일치, classification만 일치, clause만 일치, subclause 불일치 및 span 불일치.
- 행정상태 문구 누락, 완료·확정 문구와의 모순, P1의 상태 변경,
  P2 행정상태 누락 및 행정상태 evidence offset 불일치.
- 마지막 JSONL 레코드가 잘렸거나 동일 stage 레코드가 중복된 실행 저널.
- 두 프로세스가 같은 run directory에 동시에 쓰는 경우.
- 완료된 run 재실행, source 변경, model 변경 및 prompt bundle 변경.
- 비공개·부분공개 원문을 외부 LLM에 전달하는 명시적 6C 경로.
- PRISM held-out에서 조항·세부조항별 희소 strata가 유지되고, C/S 약 166건과 O 100건에 중복·누수가 없는 경우.

## Critical Paths

- 새 run: manifest 검증 → 문서 선택 → Pass 1 → journal → Pass 2 → journal → audit bridge → 기존 generation audit → 최종 manifest.
- O counterfactual: source O 보존 → 명시적 target clause/subclause →
  P1 임시 IR 폐기 → source-free 생성 → 독립 채점 → source/target 분리 audit.
- 장애 복구: Pass 1 성공 → Pass 2 실패 → 재개 → Pass 2만 재호출 → audit 완료.
- 장문 문서: 86페이지 이상 → relevance 선별 → selection hash 고정 → 두 평가 단계에서 동일 snapshot 사용.
- Live eval: 약 56건 실행 → 전수 사람 rubric → 90% 이상 8/10 및 critical label failure 0건 확인 → 실패 사례 회귀 재실행.
- PRISM classifier eval: held-out 266건 → 생성 모델 분류 → 채점 모델 분류 → 실제 source label 대비 type/C-S-O/clause/subclause 정확도와 confusion matrix 산출.
- Cutover: 신규 경로의 eval·audit 통과 → 운영 진입점 전환 → 경고 기간 → 기존 생성 경로 제거 계획 검증.
