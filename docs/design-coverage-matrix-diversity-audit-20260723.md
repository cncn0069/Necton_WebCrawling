## Problem Statement

RD-2는 실제 공공문서에서 찾은 근거와 실제 기관 메타데이터를 바탕으로 기밀(C)과
민감(S) 합성 PDF를 만든다. 다음 생산 목표는 C 30,000건과 S 30,000건이지만, 총량만
맞추면 일부 조항·문서유형·기관·본문 패턴에 결과가 몰릴 수 있다. 기관명·날짜·숫자만
다르고 본문 의미와 형식이 같은 문서가 반복되면 60,000건을 생성해도 학습 데이터의
유효 다양성은 훨씬 작다.

현재 `generate_cs_pilot.py --target-matrix`는 조항×세부조항×문서유형×행정상태 셀,
셀별 목표량, 후보 부족 예외, 생성 CSV와 `cell_report.csv`를 제공한다. 그러나 다음이
없다.

1. C/S 전체와 기관군을 포함한 생성 전 목표 배분표
2. 계획 대비 실제 분포와 부족량을 한 번에 보여주는 run 단위 리포트
3. exact duplicate, 의미 중복, 형식 반복, 동일 원문 의존도를 분리한 생성 후 감사
4. 사람이 배치당 열어볼 대표·이상 PDF 10~20건을 고르는 재현 가능한 검수 큐

이번 기능의 제품은 하나의 “다양성 점수”가 아니다. 생성 전에 60,000건의 구성을
설명하고, 생성 후에는 사람이 가장 정보량 높은 10~20건을 검수하도록 만드는 감사
계층이다.

## Demand Evidence

- 내부 사용자는 생성 CSV를 확인하고 배치당 PDF 약 10~20건을 직접 연다.
- C/S 각 30,000건 생성을 검토하면서 “문서별 고려사항도 다르고 기관별로도 다르다”는
  분포 붕괴 위험을 생성 전에 제기했다.
- 첫 번째 40건 샘플은 아직 충분히 검수되지 않았다. 따라서 현재는 의미 중복 임계값을
  고정할 근거보다, 어떤 문서를 검수해야 하는지 정하는 장치가 먼저 필요하다.

## Status Quo

```text
candidate manifest
      │
      ▼
generate_cs_pilot.py
      ├── generated.csv
      ├── cell_report.csv      (target-matrix 모드)
      └── PDFs
             │
             ▼
      사람이 CSV 확인 + PDF 10~20건 임의 검수
```

현재 `target-matrix`의 핵심 기반은 재사용할 수 있다.

- `template_matrix.py`: 유효한 24개 세부조항, 61개 세부조항×문서유형 조합,
  205개 행정상태 포함 셀
- `TargetCell`, `plan_cell()`: 목표량과 실제 후보 부족 계획
- 생성 CSV: 등급, 조항, 세부조항, 기관, 부서, 본문, 문서유형, 템플릿, seed provenance,
  모델·토큰·프롬프트 버전
- `agency_categories.py`: 5개 기관군
- candidate/extraction manifest: run과 원문 근거의 재현성

지금의 문제는 이 정보를 수집하지 않는 것이 아니라, 생성 계획과 감사 결과로 묶지
않는 것이다.

## Target User & Narrowest Wedge

대상 사용자는 EC2에서 C/S 생성 배치를 실행하고 결과 CSV와 일부 PDF를 직접 검수하는
내부 담당자 1명이다.

첫 버전의 최소 유용 범위는 다음 두 명령이다.

```powershell
python scripts/plan_cs_generation.py `
  --c-target 30000 --s-target 30000 `
  --output-dir output/audit/run-001

python scripts/audit_cs_generation.py `
  --plan output/audit/run-001/generation_plan.json `
  --input output/cs/generated.csv `
  --pdf-dir output/cs/pdfs `
  --sample-count 15 `
  --output-dir output/audit/run-001
```

첫 명령은 LLM이나 RDS 쓰기 없이 계획만 만든다. 두 번째 명령은 생성 결과를 변경하거나
차단하지 않고 감사 리포트와 검수 목록을 만든다.

## Constraints

- v1의 **품질 지표**는 생성, PDF 렌더링, RDS 반영을 자동 차단하지 않는다.
  schema, plan run ID, manifest hash 불일치 같은 **계약 무결성 오류**는 잘못된 run을
  조용히 섞지 않기 위해 fail-fast한다.
- 기존 `template_matrix.py`, 후보 manifest, 생성 CSV, 기관 분류기를 단일 진실
  공급원으로 사용한다. 병렬 taxonomy를 만들지 않는다.
- 법 조항이나 기관군만으로 레이아웃을 결정하지 않는다.
- 일반 기관도 보안·수사·소송 업무를 할 수 있으므로 기관군을 C 조항의 금지 목록으로
  사용하지 않는다.
- 기관군은 `central_ministry`, `metro_local_government`, `research_institute`,
  `education_office`, `public_corporation`의 기존 5개 값을 사용한다.
- 공식 문서 boilerplate와 법률 문구의 반복은 정상일 수 있다. 의미 유사도 하나로
  전역 제거하지 않는다.
- 첫 40건은 판정 라벨 정의와 순위 검증에 사용한다. 영구 유사도 임계값을 확정하지
  않는다.
- 원문 문서나 생성 본문을 외부 평가 서비스에 전송하지 않는다. 의미 임베딩은 EC2의
  로컬 모델로 계산한다.
- 결과는 동일 입력, 설정, seed, 모델 버전에서 재현 가능해야 한다.

## Premises

1. Coverage matrix는 생성 차단기가 아니라 생성 계획과 부족 영역을 보여주는 명세다.
2. 기존 target matrix를 확장하며 별도 조합 체계를 만들지 않는다.
3. 계획 축은 등급×조항×세부조항×문서유형×기관군×행정상태다.
4. `template_matrix.py`가 허용하는 문서유형과 행정상태만 물질화한다. 기관군은 일반
   기관의 보안 업무 가능성을 보존하기 위해 기본적으로 모든 유효 셀과 교차한다.
5. 다양성은 분포 coverage, 내용 중복, 형식 반복, 기관/내용 적합성 proxy로 분리한다.
6. exact duplicate는 전체 run에서 검사한다. 의미 중복은 같은 비교 범위 안에서만
   검사한다.
7. 첫 40건은 `duplicate`, `valid_similar`, `distinct` 라벨 규칙을 만드는 파일럿이다.
   v1은 고정 임계값 대신 nearest-neighbor 순위와 percentile을 보고한다.
8. 모든 감사 지표는 리포트 설명 또는 검수 큐 선정을 위해 존재해야 한다.

## Landscape Findings

- 층화 할당은 희소 범주 누락을 막는 표준 운영 장치지만 품질 자체를 증명하지 않는다.
- exact deduplication만으로는 의미가 같은 재작성 문서를 잡지 못한다.
- embedding 기반 semantic deduplication은 대규모 데이터의 중복을 줄이는 데 유효하다.
- 단일 전역 임계값은 공식 문서의 정상 boilerplate를 오탐할 수 있다.

프로젝트에 적용한 핵심 결론은 “한 점수”를 만들지 않는 것이다. 내용, 형식, 출처,
기관 적합성은 실패 원인과 수정 방법이 다르므로 별도 지표와 reason code로 남긴다.

## Cross-Model Perspective

독립 Codex 검토는 가장 강한 제품 정의를 “60,000건을 유효한 근거 기반 strata에
배분하고, 여러 종류의 collapse를 진단한 뒤, 실패를 가장 잘 드러낼 10~20건을 고르는
감사 가능한 실험 설계 계층”으로 정리했다.

핵심 반론은 첫 40건으로 유사도 임계값을 확정할 수 없다는 점이었다. 문서유형과
boilerplate 체계마다 최적 임계값이 다를 수 있으므로, 첫 샘플은 라벨 규칙과 의심 pair
순위를 검증하는 데만 사용한다. 이 반론을 반영해 고정 duplicate 판정 대신 순위와
percentile을 v1 출력으로 확정했다.

48시간 프로토타입 제안 중 다음을 채택한다.

- 기존 cell report를 교체하지 않고 확장
- 계획과 실제의 cell fill rate, marginal 분포, 후보 부족량 보고
- global normalized exact hash와 scope 내부 nearest-neighbor 분석
- template/structure 집중도와 shared-source 집중도 분리
- 대표와 이상 샘플마다 선정 reason code 기록

대시보드, 자동 차단, LLM 심판, 자동 재생성은 제외한다.

## Approaches Considered

### Approach A: 기존 스크립트 최소 확장

`generate_cs_pilot.py`에 plan-only를 추가하고 감사 스크립트 하나를 붙인다. 변경은
작지만 생성기가 계획·생성·렌더링 책임을 계속 함께 가지며, 의미 중복 검사가 약하다.

### Approach B: Coverage Planner + Diversity Auditor

계획과 사후 감사를 분리하고 기존 matrix와 CSV 계약을 공유한다. 로컬 임베딩 검사가
실패해도 coverage, exact hash, 형식·출처 검사는 계속 실행한다. 사람이 붙인 pair
라벨로 나중에 임계값을 보정할 수 있다.

### Approach C: 독립 Dataset Quality 플랫폼

run registry, 증분 인덱스, metric plugin, 과거 run 비교, 자동 재생성 추천까지 만든다.
장기 확장성은 좋지만 현재 사용자 1명과 수동 검수 10~20건에는 과하다.

## Recommended Approach

Approach B를 채택한다.

### 1. 데이터 흐름


### 2. Coverage cell

```python
CoverageKey = (
    classification,     # C | S
    clause_no,          # 1..8
    subclause_key,
    doc_type,
    agency_category,    # 기존 5개 기관군
    admin_status,       # 규칙 미정의는 빈 문자열
)
```

`classification`은 조항에서 결정한다. 1~4호는 C, 5~8호는 S다. 문서유형과
행정상태의 유효성은 `STATUS_AWARE_TARGETS`를 사용한다. 여기에 5개 기관군을 교차하면
현재 상한은 205×5=1,025개 셀이다. 이 규모는 CSV 계획과 메모리 집계에 충분히 작다.

기관군은 조합 금지 규칙이 아니라 목표 분포 축이다. 향후 실제 도메인 검증으로 특정
조합이 불가능하다고 확인된 경우에만 명시적인 exclusion reason을 추가한다.

### 3. 목표량 할당

입력 설정은 최소한 다음을 가진다.

```json
{
  "schema_version": 1,
  "targets": {"C": 30000, "S": 30000},
  "minimum_per_valid_cell": 5,
  "agency_weights": {
    "central_ministry": 0.20,
    "metro_local_government": 0.20,
    "research_institute": 0.20,
    "education_office": 0.20,
    "public_corporation": 0.20
  },
  "allocation_seed": 42
}
```

할당은 등급별로 독립 수행한다.

1. 모든 유효 셀에 `minimum_per_valid_cell`을 할당한다.
2. 셀 최소량이 등급 목표보다 크면 계획을 실패시키고 필요한 최소 총량을 출력한다.
3. 등급 목표를 agency weight에 따라 기관군별 필수 총량으로 먼저 나눈다. 기관군별
   총량 안에서 후보 가용성에 따라 아래 largest-remainder 방식으로 정수 할당한다.
4. 후보 가용성 가중치는 `sqrt(real_candidate_count + 1)`을 사용해 대형 source가
   나머지를 독점하지 않게 한다.
5. C의 실제 span 후보가 없는 셀은 기관 weight와 균등 cell weight만 사용하고
   `fallback_only=true`로 표시한다.
6. `planned_target` 총합은 반드시 C 30,000, S 30,000과 정확히 일치한다. 생성 후
   `attempted`, `actual_ok`, `shortage`는 별도 값이며 계획 총합과 같다고 가정하지 않는다.

계획은 `requested_target`, `real_candidate_count`, `planned_span_seeded`,
`planned_fallback`, `fallback_ratio`, `allocation_reason`을 분리한다. 후보 부족으로
실제 근거 비율을 못 맞추더라도 목표량을 조용히 다른 셀로 이동하지 않고 shortage를
남긴다.

### 4. Generation plan 계약

`generation_plan.csv`는 사람이 읽고 diff하기 위한 파생 view다. 입력으로 다시
소비하지 않는다. `generation_plan.json`만 생성기가 검증할 canonical 계약이다.

```json
{
  "schema_version": 1,
  "run_id": "sha256:...",
  "created_at": "...",
  "matrix_hash": "sha256:...",
  "candidate_manifest": {
    "run_id": "...",
    "rule_version": "..."
  },
  "allocation": {
    "seed": 42,
    "c_target": 30000,
    "s_target": 30000,
    "minimum_per_valid_cell": 5
  },
  "cells": [
    {
      "coverage_cell_key": "C|1|legal_secret|report|central_ministry|-",
      "classification": "C",
      "clause_no": "1",
      "subclause_key": "legal_secret",
      "doc_type": "report",
      "agency_category": "central_ministry",
      "admin_status": "",
      "cell_state": "fallback_only",
      "requested_target": 62,
      "real_candidate_count": 0,
      "planned_span_seeded": 0,
      "planned_fallback": 62,
      "allocation_weight": 0.00123,
      "allocation_reason": "minimum_plus_weighted_remainder"
    }
  ]
}
```

셀 필드 중 `classification`, `clause_no`, `subclause_key`, `doc_type`,
`agency_category`, `admin_status`, `cell_state`, `requested_target`은 필수다.
문자열 필드는 null을 허용하지 않고 적용 불가능한 행정상태는 빈 문자열을 사용한다.
`coverage_cell_key`는 plan 안에서 유일해야 하며 `requested_target >= 0`,
`planned_span_seeded + planned_fallback == requested_target`을 만족해야 한다.

`matrix_hash`는 유효 target, 기관군 목록, 설정의 canonical JSON hash다. 생성기는
계획의 candidate run과 현재 manifest가 다르면 기본 실패한다. 진단용 override는
명시적으로만 허용한다.

#### 4.1 Typed contract boundary

`CoverageCell`, `ExecutionSlot`, `GenerationPlan`은 표준 라이브러리의 frozen
`dataclass`로 정의한다. 각 타입은 `from_dict()`에서 필수 필드, enum 값, 음수 목표,
셀·슬롯 유일성, 합계 invariant를 검증하고 `to_dict()`에서 canonical 직렬화 입력만
반환한다. CLI와 생성기 내부에서는 검증되지 않은 plan `dict`를 전달하지 않는다.
외부 JSON은 로딩 직후 `GenerationPlan`으로 변환하며 오류에는 JSON 경로와 위반
규칙을 포함한다. 새 런타임 검증 라이브러리는 추가하지 않는다.

#### 4.2 Canonical hash boundary

plan, matrix, candidate profile, run 식별자에 쓰는 JSON hash는 공용
`canonical_json_bytes(value, normalization_version)` 하나를 거친다. 이 함수가
UTF-8, Unicode NFC, object key 정렬, compact separator, 허용 타입과 배열 정렬
전제조건을 단일하게 적용한다. 목적별 함수(`compute_matrix_hash()`,
`compute_candidate_profile_digest()`, `compute_plan_run_id()`)는 도메인 필드 선택과
version tag만 담당하고 직렬화 규칙을 다시 구현하지 않는다. content raw/normalized
hash는 JSON 계약 hash와 입력 형태가 다르므로 별도 함수로 두되 normalization version을
artifact에 기록한다.

### 5. 생성기 연동

`generate_cs_pilot.py`는 `--coverage-plan <json>`을 선택적으로 받는다.

- 미지정: 기존 `--per-clause`, `--target-matrix` 동작을 그대로 유지한다.
- 지정: plan의 cell별 목표를 `(coverage_cell_key, coverage_slot,
  agency_category, seed_mode)` 실행 슬롯으로 먼저 펼친 뒤 생성기가 그 슬롯만
  소비한다. 생성 도중 기관군을 다시 무작위 선택하거나 목표를 재계산하지 않는다.
- `--coverage-plan`과 기존 목표량 플래그를 동시에 주면 CLI error로 종료한다.
- 각 생성 행에 `coverage_cell_key`, `coverage_slot`, `agency_category`,
  `coverage_plan_run_id`를 기록한다. `(coverage_plan_run_id, coverage_cell_key,
  coverage_slot)`은 유일하다.
- planner는 span 후보의 실제 기관을 기존 `resolve_agency_for_candidate()`로 한 번만
  해석하고 `get_agency_category()`를 적용한다. 결과는 candidate ID와 extraction ID를
  key로 한 versioned `candidate_profiles.jsonl`에 저장한다. 생성기는 같은 run에서 이
  index를 재사용해 N+1 기관 조회와 계획/생성 분류 차이를 막는다.
- 후보에 source/doc ID가 없거나 실제 기관을 찾지 못한 정상적인 미해석은
  `profile_status=unresolved`와 reason code로 저장하고 fallback/shortage 계산에
  반영한다. DB 연결·timeout·query 오류는 unresolved로 변환하지 않고 planner 전체를
  실패시킨다.
- 문서별 기관 source는 후보마다 `LIKE` 쿼리를 실행하지 않는다. 후보에 필요한 고유
  `(source, doc_type)` 조합을 먼저 구하고 기존 복합 인덱스로 관련
  `body_file_path, ordering_agency` 행을 batch preload한 뒤 경로의 doc ID를 파싱해
  메모리 lookup index를 만든다. DB query 수는 후보 수가 아니라 고유 source/doc-type
  조합 수 이하이어야 한다.
- span 후보는 subclause, doc type, agency category로 한 번만 bucket한다.
- fallback 기관 샘플은 기관군별로 미리 bucket해 원하는 category에서 선택한다.
- 원하는 기관군의 후보가 부족하면 임의의 다른 기관군으로 대체하지 않고 fallback과
  shortage reason을 기록한다.
- resume 시 plan run ID와 row의 plan run ID가 다르면 이어쓰지 않는다.

후보 프로파일링, 셀 할당, 실행 슬롯 전개는 CLI와 LLM 호출에서 분리된 순수 library
경계로 둔다. `generate_cs_pilot.py`는 plan 로딩·검증과 실행 오케스트레이션만 맡고,
기존 `generate_cell_rows()`에 기관군 보정 분기를 누적하지 않는다. 이 경계가
coverage plan을 사후 통계가 아니라 재현 가능한 실행 계약으로 만든다.

기존 `cell_key`와 `cell_report.csv`는 하위 호환을 위해 유지한다. 새
`coverage_cell_key`는 기관군을 포함한 확장 key다.

### 7. 다양성 지표

#### 7.1 분포 coverage

- cell fill rate: `planned_target > 0`일 때 `actual_ok / planned_target`; excluded/zero
  target은 계산에서 제외하고 `not_applicable`로 별도 집계
- absolute shortage와 overfill
- 각 축의 planned/actual marginal 분포
- zero candidate, fallback-only, generation-error 셀 수
- 동일 seed source의 최대 점유율

#### 7.2 Exact duplicate

두 hash를 분리한다.

- `raw_content_hash`: 제목+본문의 공백/Unicode만 canonicalize
- `normalized_content_hash`: 기관명, 날짜, 전화번호, 문서번호 같은 표면 변형을
  typed placeholder로 치환한 뒤 hash

숫자를 모두 삭제하지 않는다. 금액·인원·기간·사건번호를 서로 다른 placeholder type으로
치환하되 원래 값과 값 hash는 v1 artifact에 남기지 않는다. raw가 같으면 확정 exact duplicate,
normalized만 같으면 templated duplicate candidate로 보고한다.

#### 7.3 의미 유사도

- 한국어를 지원하는 로컬 sentence embedding 모델을 설정으로 지정한다.
- 모델 이름, revision, embedding dimension, normalization 설정을 summary에 기록한다.
- 비교 scope 기본값은 같은 `classification + subclause + doc_type`이다.
- 행정상태와 기관군은 scope 내부 attribute로 유지해, 서로 다른 기관군이지만 본문이
  같은 문제를 찾을 수 있게 한다.
- 전역 all-pairs 비교를 하지 않는다. scope별 chunked top-k nearest-neighbor만 구한다.
- v1은 similarity 값, scope percentile, reciprocal pair 여부, shared-source 여부를
  출력하며 duplicate 여부를 자동 확정하지 않는다.
- embedding 모델 로딩이나 추론이 실패하면 해당 section을 `unavailable`로 표시하고
  나머지 감사를 완료한다.

#### 7.4 형식 반복

PDF 이미지 유사도 대신 CSV 메타데이터와 생성 본문의 구조 fingerprint를 사용한다.

v1 fingerprint는 generated CSV에서 결정적으로 얻을 수 있는 값만 사용한다.

```text
structure_fingerprint = hash(
  template_id,
  doc_type,
  paragraph_count_bucket(body_text),
  numbered_list_count_bucket(body_text),
  body_length_bucket(body_text)
)
```

ordered heading과 table 구조는 현재 CSV 계약에 없으므로 v1 fingerprint에 넣지 않는다.
향후 renderer가 `section_signature`와 `table_count`를 직접 내보낼 때만 추가한다.

리포트에는 template concentration, fingerprint concentration, 가장 큰 fingerprint
cluster와 기관군별 template 분포를 기록한다. 동일 template 반복 자체는 실패가 아니며,
특정 셀 또는 기관군이 하나의 fingerprint에 과도하게 몰렸을 때 anomaly가 된다.

#### 7.5 기관/내용 적합성 proxy (v1d only)

v1d도 LLM 판정을 하지 않는다. 기존 기관군과 세부조항 keyword evidence를 사용해 다음을
의심 신호로만 기록한다.

- 기관군과 source 기관군 불일치
- subclause를 뒷받침하는 본문 cue가 전혀 없음
- fallback 기관·업무·문서유형 조합이 계획에는 있으나 실제 샘플 근거는 없음

`proxy`라는 이름과 reason code를 유지하며 품질 실패로 자동 확정하지 않는다.

### 8. 검수 샘플 선정

기본 `sample_count=15`, 허용 범위 10~20이다. 동일 seed로 같은 목록을 만든다.

먼저 anomaly quota를 `min(10, ceil(sample_count * 2 / 3))`건 채운다.

1. raw exact duplicate
2. normalized duplicate candidate
3. scope 내 최고 의미 유사 pair
4. 가장 부족한 cell의 생성 성공 문서
5. 가장 큰 format cluster의 중심/경계 문서
6. 동일 seed source 집중 문서
7. 기관 적합성 proxy mismatch

나머지는 representative quota다.

- 주요 coverage cell에서 embedding centroid에 가장 가까운 문서
- 임베딩을 사용할 수 없으면 normalized token centroid에 가까운 문서
- 같은 cell, 같은 reason, 같은 seed source가 검수 목록을 독점하지 않도록 cap 적용

한 row에 여러 사유가 있으면 위 목록의 순서를 primary reason 우선순위로 사용하고
나머지는 `secondary_reasons`에 보존한다. pair anomaly는 두 문서를 모두 넣지 않고
reason별 ranking key가 높은 row 하나를 기본 선택하며 `related_row_id`로 상대를
가리킨다. 서로 다른 metric을 하나의 anomaly score로 합치지 않는다.
동점은 `(reason_priority, -metric_value, coverage_cell_key, row_id)` 순으로 끊는다.
cell당 최대 2건, seed source당 최대 2건을 적용하고 quota가 남으면 cap을 1씩 늘려
재순회한다.

`review_samples.csv` 필드:

```text
sample_rank, row_id, sample_kind, reason_code, secondary_reasons, reason_detail,
coverage_cell_key, metric_name, metric_value, related_row_id,
seed_candidate_id, seed_extraction_id, pdf_path
```

모든 검수 문서는 “왜 선택됐는지” 설명할 수 있어야 한다.

### 10. 실패 처리

- plan schema/version 오류: 생성 전에 명확히 실패
- matrix/candidate manifest hash 불일치: 기본 실패, 명시적 override만 허용
- generated CSV 필수 필드 누락: 감사 실패, 누락 필드 목록 출력
- 일부 malformed row: row error CSV에 기록하고 나머지 감사 지속
- embedding unavailable: semantic section만 unavailable, 다른 리포트 정상 생성
- PDF 없음/열기 실패: review sample에 `pdf_unavailable` reason 추가
- 출력 디렉터리 기존 run과 충돌: `--resume` 또는 새 run ID 없이는 덮어쓰지 않음
- 감사 중단 후 재실행: 입력·설정 hash가 같으면 embedding cache 재사용

### 11. 성능 설계

60,000건 전체 all-pairs는 약 18억 pair라 금지한다. 기본 비교 scope는 같은
등급+세부조항+문서유형이며 scope별 top-k만 구한다.

- CSV 집계와 hash: O(N)
- embedding: batch encode, float32/float16 설정 가능
- neighbor 검색: scope별 chunked cosine top-k
- embedding cache key: model revision + normalized text hash
- 메모리 상한과 batch size는 CLI 설정으로 제한
- 진행률은 processed rows/scopes와 ETA를 출력

sentence-transformers는 선택 dependency로 둔다. 설치되지 않았거나 모델이 캐시에 없고
오프라인이면 semantic section을 unavailable로 완료한다. benchmark 전 임시 안전 상한은
scope 5,000건이지만 실제 실행은 run 설정의 per-scope·total comparison budget을 모두
통과해야 한다. 하나라도 넘는 scope는 `requires_index`로 보고하고 exact quadratic
비교를 실행하지 않는다. 외부 vector
service는 도입하지 않으며, v1c에서 로컬 FAISS/HNSW 중 하나를 benchmark 후 선택한다.

### 12. 구현 정밀 계약

#### 12.1 Cell 상태와 열거

셀 상태는 다음 세 값만 허용한다.

- `matrix_valid`: template/status 조합이 유효하고 실제 후보가 1건 이상
- `fallback_only`: matrix는 유효하지만 실제 후보가 0건
- `excluded`: 명시적인 exclusion rule이 있으며 계획 목표는 항상 0

`matrix_valid`와 `fallback_only`는 최소량을 받는다. `excluded`는 받지 않는다.
`evidence_supported`는 배타적 state가 아니라 할당 후 계산하는 boolean이다.

```python
for target in sorted(STATUS_AWARE_TARGETS, key=target_sort_key):
    classification = "C" if target.clause_no in {"1", "2", "3", "4"} else "S"
    for agency_category in sorted(AGENCY_CATEGORIES):
        key = CoverageKey(classification, target.clause_no, target.subclause_key,
                          target.doc_type, agency_category, target.admin_status or "")
        if key in explicit_exclusions:
            emit(key, state="excluded", requested_target=0)
        else:
            count = candidate_profile_counts.get(key, 0)
            state = "fallback_only" if count == 0 else "matrix_valid"
            emit(key, state=state, real_candidate_count=count)
```

예: `(5, bid_contract, bid_notice)`에 `공고 전` 상태가 있고 exclusion이 없다면
5개 기관군 셀이 생긴다. `bid_notice`에 정의되지 않은 `감사 진행 중` 상태는
`STATUS_AWARE_TARGETS`에 없으므로 생성되지 않는다.

#### 12.2 할당 공식과 tie-break

등급별 목표 `T`는 먼저 agency weight로 기관군 총량 `T_a`에 exact-total largest
remainder 할당한다. 동점은 agency category 이름 오름차순으로 끊는다. 따라서 20%
weight는 후보 수와 무관하게 해당 등급 목표의 20% 기관군 marginal을 요구한다.

기관군 `a`의 non-excluded 셀 수를 `n_a`, 목표를 `T_a`, 최소량을 `m`이라 한다.
`T_a < n_a*m`이면 계획은 실패한다. 그 기관군 안의 각 셀 `i` weight는 다음과 같다.

```text
candidate_factor_i = sqrt(real_candidate_count_i + 1)
raw_weight_i = candidate_factor_i
normalized_weight_i = raw_weight_i / sum(raw_weight)
base_i = m
quota_i = (T_a - n_a*m) * normalized_weight_i
floor_i = floor(quota_i)
remainder_i = quota_i - floor_i
```

먼저 `base_i + floor_i`를 할당하고 남은 건수는 `remainder_i` 내림차순으로 1건씩
배정한다. 동점은 canonical `coverage_cell_key` 오름차순으로 끊는다.

축소 예: 목표 20, 셀 3개, 최소 2, normalized weight가 0.5/0.3/0.2이면 남은 14의
quota는 7.0/4.2/2.8이다. floor 적용 후 7/4/2, 남은 1건은 remainder 0.8인 세 번째
셀에 배정되어 최종 목표는 9/6/5이고 합은 정확히 20이다. 같은 절차를 각 기관군에
적용한 뒤 합치므로 기관군 필수 marginal과 등급 총량을 모두 보존한다.

#### 12.3 Canonical hash와 재현성

- UTF-8, NFC, JSON object key 사전순, 배열은 명시된 canonical sort key 순
- 정수는 JSON integer, 소수 weight는 소수점 아래 12자리 반올림
- separator는 `(',', ':')`, `ensure_ascii=false`
- Windows path는 repo-relative POSIX `/` 경로로 변환
- `created_at`, output path, 실행 host는 `matrix_hash`와 `run_id` 입력에서 제외
- 구현 git commit, schema version, normalization rule version, allocation seed,
  candidate manifest ID, source ordering version은 run manifest에 포함
- 입력 row 정렬은 `(coverage_cell_key, coverage_slot, row_id)`로 고정

`run_id = sha256(canonical(plan_without_run_id_and_created_at))`로 계산한다.

#### 12.4 Artifact schema

| Artifact | Primary key | 필수 내용 |
|---|---|---|
| `generation_plan.json` | `run_id`; cell의 `coverage_cell_key` | plan metadata와 위 cell 필드 전체 |
| `generation_plan.csv` | `coverage_cell_key` | JSON cell의 사람이 읽는 파생 view |

#### 12.5 입력 무결성 정책

| 위반 | 처리 |
|---|---|
| 중복 `row_id` 또는 중복 coverage slot | fail-fast |
| plan run ID 불일치 | fail-fast |
| 알 수 없는 등급/기관군/상태 | row 격리 후 run `degraded` |
| plan에 없는 coverage cell | row 격리 후 run `degraded` |
| 계획 slot 누락 | shortage 집계, run `degraded` |
| PDF 누락/열기 실패 | audit 지속, review reason 기록 |
| body가 비어 있음 | row 격리, coverage actual error 집계 |

run 상태는 `complete`, `degraded`, `failed`다.

- `complete`: 계약 오류가 없고 `actual_ok == planned_target`
- `degraded`: 감사 산출물은 완성됐지만 row error 또는 shortage가 있음
- `failed`: 계약 무결성 fail-fast, 필수 artifact 생성 실패, 또는 `actual_ok == 0`

품질 anomaly 수는 run 상태를 바꾸지 않는다.

#### 12.6 Normalization 규칙

`normalization_version=content-normalize-v1`을 기록한다. 적용 순서는 긴 패턴부터
`문서번호 → 사건번호 → 전화번호 → 날짜 → 금액 → 인원 → 일반 숫자`다. 각 값은
`<DOCNO>`, `<CASE_NO>`, `<PHONE>`, `<DATE>`, `<MONEY>`, `<COUNT>`, `<NUM>`으로
치환한다. 원본 값이나 값 hash는 v1에서 보관하지 않는다. 법 조항 번호와 section
numbering은 치환하지 않는다. 기관명은 exact
`ordering_agency` 값과 알려진 별칭만 `<AGENCY>`로 바꾸며 임의 NER은 하지 않는다.
각 규칙에는 한국어 날짜, 주민번호처럼 보이는 숫자, 금액, 조 번호, 문서번호의
충돌 fixture를 둔다.

#### 12.7 Semantic top-k 기본값

- `top_k=10`, scope 최소 크기 2
- size 0/1: pair 없음, status `insufficient_scope`
- size 2..k: 자기 자신을 제외한 모든 이웃
- percentile population: 같은 scope에서 생성된 모든 top-k edge의 similarity
- 동점 이웃: similarity 내림차순 후 neighbor row ID 오름차순
- reciprocal: A의 top-k에 B, B의 top-k에 A가 모두 포함
- `semantic_scope_key = classification|subclause_key|doc_type`
- sampling cap은 `coverage_cell_key`를 사용한다. 두 key를 섞지 않는다.

#### 12.8 Pair label 사용

`pair_labels.csv`의 label은 `duplicate`, `valid_similar`, `distinct`다. reviewer ID와
`label_version`은 필수다. 한 reviewer로 시작하되 같은 pair의 최신 label만 평가에
사용한다. 추후 복수 reviewer가 생기면 불일치 pair는 `disputed`로 분리하고 임계값
학습에서 제외한다. 첫 40건은 sampler의 suspicious-pair precision@k와
representative coverage를 평가하며 영구 threshold를 만들지 않는다.

### 13. 단계별 전달 범위

Approach B의 최종 구조는 유지하되 한 번에 모두 구현하지 않는다.

1. **v1a Plan:** schema, cell enumeration, candidate profile, exact-total allocation,
   plan-only CLI
2. **v1b Core audit:** coverage actual, exact/normalized hash, source/template 집중도,
   reason-coded review sampler
3. **v1c Semantic:** 모델·라이선스·CPU/GPU benchmark, scope top-k, cache, pair labels
4. **v1d Optional proxy:** 실제 배치에서 가치가 확인된 metadata mismatch만 추가

agency-fit keyword proxy와 자동 문맥 적합성 판정은 v1d 전까지 제외한다. JSON이 유일한
canonical 입력이며 CSV는 파생 view다.

### 14. 남은 결정 규칙

#### 14.1 후보 capacity와 span/fallback 분할

`max_rows_per_candidate` 기본값은 1이다. 한 실제 후보가 여러 합성 행을 seed하지 않게
해 source 집중을 줄인다. 설정을 올리면 plan hash가 달라지며 리포트에 반드시 표시한다.

```text
candidate_capacity = real_candidate_count * max_rows_per_candidate
planned_span_seeded = min(requested_target, candidate_capacity)
planned_fallback = requested_target - planned_span_seeded
candidate_shortage = max(0, requested_target - candidate_capacity)
evidence_supported = candidate_shortage == 0
```

candidate shortage는 계획 target을 줄이지 않는다. 그만큼 fallback으로 채우되 계획에
명시한다. 생성 호출 실패로 생기는 실제 `shortage`와 혼동하지 않는다.

#### 14.2 대표 샘플의 결정적 선택

anomaly를 채운 뒤 representative quota `R`을 다음처럼 배분한다.

1. `actual_ok > 0`인 cell을 `(planned_target desc, shortage_ratio desc,
   coverage_cell_key asc)`로 정렬한다.
2. cell당 1건씩 round-robin하고, cell 수가 `R`보다 작으면 같은 순서로 2회차를 돈다.
3. semantic embedding이 있으면 cell embedding centroid를 O(N)으로 계산하고 centroid와
   cosine distance가 최소인 row를 선택한다. 동점은 row ID 오름차순이다. all-pairs
   medoid는 계산하지 않는다.
4. embedding이 없으면 body length의 median과 가장 가까운 row를 선택하고, 차이 동점은
   normalized content hash, row ID 오름차순으로 끊는다.
5. 이미 anomaly로 선택된 row, cell cap, source cap에 걸린 row는 다음 후보로 넘어간다.
6. 모든 cap 때문에 quota가 남으면 source cap, cell cap 순으로 1씩 늘려 재순회한다.

cross-metric anomaly score는 만들지 않는다. anomaly는 reason priority로 먼저 나누고
각 reason 안에서만 다음 ranking key를 쓴다.

| Reason | Ranking key |
|---|---|
| raw exact duplicate | duplicate group size desc, row ID asc |
| normalized duplicate | group size desc, row ID asc |
| semantic neighbor | similarity desc, reciprocal first, row ID asc |
| coverage shortage | shortage ratio desc, planned target desc, row ID asc |
| format concentration | fingerprint group size desc, row ID asc |
| shared source | source share desc, row ID asc |
| agency proxy (v1d only) | fixed rule severity desc, row ID asc |

현재 phase에서 `not_run` 또는 `unavailable`인 reason category는 sampler가 건너뛰고
남은 category와 representative quota로 rollover한다.

#### 14.3 Exact canonicalization

`raw_content_hash` 입력은 다음 순서로 만든다.

1. title과 body를 각각 Unicode NFC로 변환한다.
2. CRLF와 CR을 LF로 변환한다.
3. 각 줄의 앞뒤 공백을 제거한다.
4. 줄 내부의 연속 space/tab/NBSP를 ASCII space 하나로 합친다.
5. 연속 빈 줄은 빈 줄 하나로 합친다.
6. 전체 앞뒤 빈 줄을 제거한다.
7. `title + "\n<SECTION:BODY>\n" + body`를 UTF-8 encode해 SHA-256한다.

NFKC는 글자 모양 차이를 합칠 수 있어 사용하지 않는다. normalized hash는 위 결과에
`content-normalize-v1` placeholder 규칙을 적용한 뒤 계산한다. placeholder로 치환된
원본 값과 그 hash는 v1 artifact에 저장하지 않는다. normalized duplicate 판단에는
placeholder 문자열만 사용한다.

#### 14.4 Candidate profile digest

`candidate_profiles.jsonl`은 candidate manifest의 run ID, rule version,
candidate artifact SHA-256 목록, resolver version, agency-category rule version,
정렬된 profile row의 canonical hash를 포함하는 `_profile_manifest.json`과 함께 쓴다.
`candidate_profile_digest`는 이 manifest의 canonical SHA-256이다. plan JSON,
generated run metadata, audit summary 모두 같은 digest를 기록하며 불일치 시 fail-fast다.

#### 14.5 Atomic artifact publication

planner와 auditor는 run 산출물을 같은 디렉터리의 임시 파일에 모두 작성하고 schema,
행 수, digest를 검증한 다음 `os.replace()`로 최종 이름에 게시한다. 개별 artifact
rename이 끝난 뒤 `_manifest.json`을 completion marker로 가장 마지막에 atomic
게시한다. 소비자는 manifest가 없거나 manifest에 선언된 파일·digest가 하나라도
불일치하면 해당 run을 미완료로 거부한다. 새 run ID 디렉터리에만 게시하며 기존 완료
run을 덮어쓰지 않는다.

#### 14.6 Semantic 실행 상태와 계산 budget

summary의 semantic 상태는 다음 enum이다.

- `ok`: 모든 eligible scope 완료
- `partial`: 일부 scope만 완료하고 나머지는 `requires_index`
- `requires_index`: eligible scope가 있으나 하나도 budget 안에서 완료되지 않음
- `unavailable`: dependency/model/runtime 실패
- `not_run`: v1a/v1b 또는 사용자가 비활성화
- `insufficient_data`: 모든 scope 크기가 0 또는 1

scope별로도 `ok|requires_index|insufficient_scope|error`를 기록한다. semantic review
candidate는 `ok` scope에서만 고른다.

summary aggregation은 모든 eligible scope가 완료되면 `ok`, 완료와
`requires_index|error`가 섞이면 `partial`, 전부 budget 초과이면 `requires_index`,
전부 error이면 `unavailable`, 크기 0/1뿐이면 `insufficient_data`다.

model spike가 `max_exact_scope_size`와 `max_exact_comparisons_total`을 결정한다. auditor는
canonical scope key 순서로 `n*(n-1)/2`를 누적하고, scope 제한 또는 총 budget을 넘는
scope를 `requires_index`로 남긴다. 초기 5,000은 제품 기본값이 아니라 benchmark 전
안전 상한이며 설정과 run manifest에 기록한다.

#### 14.8 출력 cardinality와 truncation

- plan/coverage rows: 최대 valid cell 수, 현재 1,025
- review rows: 최대 20
- row errors: 입력 row 수 이하, 60,000
- cosine pair 후보: directed `N*top_k` 이하, canonical undirected pair로 합친 뒤
  `max_pair_rows=200,000` 기본 cap
- exact duplicate pair를 완전 조합으로 펼치지 않는다. group ID와 representative pair만
  쓰고 group size는 summary에 기록한다.
- pair cap 초과 시 similarity/rank 순으로 상위 row만 CSV에 기록하고 전체 histogram,
  scope별 counts, truncation count는 summary에 남긴다.
- 10,000행을 넘는 CSV는 `.csv.gz`로 쓰며 summary artifact manifest에 압축 여부를 기록한다.
- 전체 artifact 500 MiB 예상치를 넘으면 verbose pair diagnostics를 중단하고 summary와
  review sample은 끝까지 작성한다. run은 `degraded`가 아니라 audit section
  `truncated=true`로 표시한다.

#### 14.9 Non-semantic streaming

v1b auditor는 입력 CSV를 한 번 순차적으로 읽는다. 현재 행의 본문은 raw/normalized
hash와 필요한 fingerprint를 계산한 뒤 버리고, 메모리에는 coverage counter,
hash별 count·최소 representative row, 제한된 anomaly/review 후보만 유지한다.
최종 정렬은 전체 원문 행이 아니라 집계 key와 bounded review 후보에만 적용한다.
일반 경로에서 `list(csv.DictReader(...))` 또는 전체 body text 컬렉션을 만들지 않으며
새 dataframe dependency를 추가하지 않는다.

## Success Criteria

- C 30,000건과 S 30,000건의 `planned_target` 합이 등급별 목표와 정확히 일치한다.
- `attempted`, `actual_ok`, `error`, `shortage`를 계획 총량과 분리해 보고하고 run 상태가
  위 계약에 따라 `complete|degraded|failed` 중 하나로 결정된다.
- 유효하지 않은 문서유형·행정상태 조합은 계획에 생성되지 않는다.
- 5개 기관군과 205개 기존 status-aware 셀의 목표·실제 분포를 조회할 수 있다.
- 동일 입력·설정·seed에서 plan과 review sample row ID가 동일하다.
- 구현 commit, source ordering, normalization version, embedding runtime, 모든 tie-break
  입력이 run manifest에 기록된다.
- 계획과 다른 candidate manifest 또는 matrix를 생성기가 조용히 소비하지 않는다.
- raw exact duplicate fixture의 100%를 탐지한다.
- normalized duplicate와 의미 유사 문서를 자동 삭제하거나 실패 확정하지 않고 pair와
  reason으로 보고한다.
- 의미 비교가 설정된 scope 밖으로 새지 않는 테스트가 있다.
- embedding 실패 시 coverage, exact, format, source concentration, review sample 리포트가
  완성되고 semantic은 `unavailable`, agency proxy는 v1d 전 `not_run`이다.
- 검수 목록은 10~20건이며 모든 행에 reason code와 PDF 경로 또는 불가 사유가 있다.
- `pair_labels.csv`로 suspicious-pair precision@k와 representative cell coverage를
  계산할 수 있다.
- 기준 EC2의 instance type, CPU/GPU, RAM을 benchmark artifact에 기록한다. 60,000건
  non-semantic audit는 5분·peak RSS 2 GiB·출력 500 MiB 이하를 통과해야 한다.
- semantic 단계는 선택 모델 spike에서 60,000건 또는 worst-scope fixture 기준 CPU
  60분/GPU 15분·peak RSS 8 GiB 이하를 통과한 모델/index만 채택한다. 기준을 못 맞추면
  semantic section은 `requires_index`로 남기고 v1b 출시는 막지 않는다.
- 기존 `--per-clause`, `--target-matrix`, `cell_report.csv` 동작이 회귀하지 않는다.
